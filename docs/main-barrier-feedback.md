准备局面：林小满持路障道具BARRIER和遥控骰卡，三位AI保留原逻辑。从背包选择道具、取消一次后重新设置到1号地；再实际使用遥控骰6。角色被截停在1号地，路障消失；实际购地850后，进入顾田野AI回合并观察到正常掷骰。不是自然完整对局，未直接调用引擎伪造使用。

基线截图barrier-feedback-baseline-placed.png看不见刚放置的障碍，也没有设置说明。代码核实：syncBoardAssets(true)先依据道路实体创建路障，随后地产循环用property.hasObstacle=false再次同步，删掉刚创建的道具模型；但道路实体仍存在，因此会截停玩家。实际落点和实体移除证明道具规则仍生效。

## 最小修复

地产同步同时考虑现有道路BARRIER实体，避免用另一套旧地产标志覆盖道具外观。复用原路障模型，不增加素材或新系统。设置成功后用现有非模态提示说明地名、首位进入者截停、自己也会触发、触发后移除；不新增等待。

改main.js的外观同步与PresentationUI描述，并在GameEngine已有成功设置结果上补发ROAD_ENTITY_CHANGED展示事件；未改结算。卡片/道具规则、AI、120格地图、经济和存档格式不变。下一回合AI可能再用路障卡，不能把之后出现的旧卡片障碍误认作道具未移除。

首次改后模型已恢复，但检查发现useItem只发INVENTORY_CHANGED，未传播路障设置结果，提示断言未通过。保留barrier-feedback-missing-event-*；补发已有结果事件，使人类与AI一致进入表现层，不消耗第二个道具。
