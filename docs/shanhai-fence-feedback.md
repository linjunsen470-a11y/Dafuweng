# 围栏截停的原因与余步提示（2026-11-06）

## 实测问题

两图四人准备局中，人类在0号选择遥控6步，前方1号设有围栏；实际只走1步便停在自有地产。修改前骰子仍显示“掷出6步”，操作区只显示升级或路过，没有说明余下5步取消、围栏已经移除。核心返回了OBSTACLE_CONSUMED事件，但章节没有使用它进行解释，原日志也没有为本次围栏截停生成独立记录。

另外复现第四位AI从相同的未完成6步移动存档继续行动，原回顾只展示最终地点、现金和经营变化，没有截停原因。两图均通过真实页面确认，见qa/fence-feedback-baseline-report.json。

## 修复

仅在规则引擎实际返回OBSTACLE_CONSUMED后记录本次展示信息，不从地图上围栏消失或最终地点猜测。记录角色、围栏地点、已走步数及取消余步，不改变引擎移动结果。

复用原操作区的行程提示位置，显示例如：“围栏截停：原定6步，实际走1步，在1号停下；剩余5步取消，围栏已移除。本站仍照常处理。”骰子文字同步为原定步数与实际截停地点。如果围栏恰在最后一步，明确已走完本次步数，不提示取消0步。

AI在既有折叠回顾标题下直接显示同类说明，不用展开日志。没有新弹窗、地图遮罩、动画等待或额外操作按钮，快速模式和减少动画行为不变。

新增一个可选的slice.lastMovementStop展示字段，仍沿用存档version 1。刷新可恢复本次说明，途中存档也从原pendingMove.path计算实际步数；新回合清除。旧存档缺少该字段时保持无提示，不伪造历史。没有永久流水、规则字段、经济参数或AI决策改动。
