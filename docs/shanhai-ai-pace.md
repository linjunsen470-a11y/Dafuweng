# 三人短局：AI速览与及时回顾

本轮基于 `b09269b8c48571f3aa2e867113957978f097c95f`，继续独立分支 `cloud/dafuweng-playability`。没有修改经济、AI策略或破产规则。

## 先试玩，再选范围

使用当前公开的 `SliceSession.start({seed:314,playerCount:3,maxRounds:3})` 创建合法初始存档，在真实 Chromium 页面从首轮玩至三轮结算。没有跳过中间回合、强制获胜或减少动画；正常动作偏好、1×速度、静音。玩家实际掷骰、买地及结束回合，六次AI行动均正常执行。三轮上限仅用于本轮短局验证；正式启程页仍默认16轮。

两名AI连续行动的等待分别约 6.932、11.165、6.513 秒，总计24.610秒。当前行动者显示正确，但第一名AI已经完成时，第二名行动期间回顾仍完全隐藏。第三轮正常结算；这不是依据一局胜负调整经济。

另复核破产机制：当前章节统一放弃破产地产竞拍，底层清算解除产权、抵押与等级后重新开放购买，不会阻断两个存续玩家继续竞争。完整竞拍还需要处理AI途中暂停、等待玩家报价、多个地块队列及刷新续接，超过本轮选定的等待体验切片，故没有加入临时竞拍或隐蔽自动竞价。

## 实际改动

回合顶部新增「AI逐步 / AI速览」按钮，可点击或键盘切换。只压缩AI掷骰、逐格移动、乘船与回合停顿，并让AI能力动作继续播放时不阻塞后续行动；所有规则命令、费用、落地、存档和日志仍执行。玩家动作依然使用原来的1×/2×设置。正在播放的动作片段完成后，后续片段采用新设置。

设置使用独立偏好键 `shanhai:ai-quick`，跨地图、刷新保留；无法访问或写入存储时仍能在当前页面切换。不修改游戏存档结构或地图存档槽，旧存档沿用原逻辑。

回合顶部持续显示当前AI姓名、轮次、存续AI席次和观看方式。第一名AI结束后立即开放其回顾，无需等待第二名；已完成者会在进度提示中列出。玩家破产后的旁观提示说明剩余AI继续至结算；此时也能开启速览。连续旁观只保留当前一轮的AI回顾，避免退出后堆积大量面板。

## 实际页面结果

最终构建下，三轮对应的AI等待为5.194、5.399、3.018秒，总计13.611秒，比基线24.610秒减少约45%。第一轮包含在AI行动中手动开启速览的操作时间。前后玩家状态、产权、胜者、故事/能力进度以及按顺序的日志消息一致；只排除了日志的真实时钟显示。采样确认第二名AI行动时已能阅读第一名的回顾。

390像素手机视口在枫谷以默认双人模式完成购地和AI回合，刷新后玩家与产权不变；速览偏好跨图保留，空格可切回逐步，普通动作按钮仍保持1×。目视检查按钮与破产旁观提示无横向挤压。

破产边界采用明示的山城低现金/高租金存档，再从页面实际遥控落地、付租与清算：3号地产恢复无主，界面说明统一放弃；点击继续后显示旁观提示，途中开启速览，两名AI完成剩余两轮并正确结算，回顾面板不超过当前一轮两条。该场景不是自然短局发生的破产。

页面无报错。核验脚本：`node test-shanhai-ai-pace.js baseline`（改动前基线）与 `node test-shanhai-ai-pace.js quick`（当前构建）；截图仅内部检查，未提交或上传。

## 验证与边界

- 14项相关测试通过：三人轮转、产权/收租、旧双人存档、AI2续接、破产清算和跳过、结算，以及AI回顾的真实资产/日志差异。
- `npm run build:shanhai` 通过。仍有原有的大JS分块提示；本轮未新增依赖或素材。
- 页面比较与边界验证结果见 `qa/ai-pace-quick-report.json`；基线见 `qa/ai-pace-baseline-report.json`。日志的真实时钟字段在两次游玩间自然不同，比较时仅排除该显示时间，保留消息顺序和内容比较。

未跑全量测试或长期经济模拟。等待时间来自一次同种子软件WebGL环境的浏览器自动操作，包含页面操作和渲染开销，不能代表真实手机性能。速览不等于零等待，短促动作与音效节奏的主观体验仍待进一步观察。破产竞拍、联机与额外席位均未增加；此前主观音乐试听的缺口仍在。

下一步可单独补齐可恢复的破产竞拍交互，或继续观察更长三人局的等待与信息负担，保留这轮速览作为可关闭的选项。
