# 自动偿债明细（2026-11-06）

## 先复现的问题

先以固定种子314在两图各跑一场四人、默认16轮完整规则对局，分别经过57/61次循环到达终局（包含既有AI和玩家固定经营策略）。记录见qa/debt-season-observation.json。山城出现银行操作；这两个样本没有自然触发欠租，不能据此判断平衡或破产频率。

随后用准备好的第14轮四人存档，在真实浏览器通过遥控骰走到对手四级地产，对比“现金200、存款3000”和“现金200、存款100”两种情况。海岸租金1610，山城1470；前者自动提取1410/1270存款付清，后者只支付300后破产。修改前操作区只显示已付租金或笼统的破产文字，没有解释存款减少多少、是否已经动用存款、到底还差多少；最近动态可能随着后续AI行动滚出。

两图的破产准备局还通过页面旁观至第16轮结算。完整16轮检查是规则模拟，页面验证为准备存档的中后期片段，不声称从零手工试玩完两场。

## 修复范围

在现有操作区增加一个简短、无需额外点击的“本次自动偿债”明细，仅发生自动偿债时出现：

- 显示角色、地点、债权人、应付租金及实际支付；成功时明确“已付清，本次没有破产”，破产时列出未付差额。
- 列出自动动用存款金额，以及实际发生的股票出售、建筑出售和地产抵押回笼资金。展示当前现金和剩余存款。
- 解释现金不足先动用存款，再依原规则变现资产，仍不足才破产；已提取的部分不再赚利息，后续按届时存款余额结息。
- 破产时明确本明细是破产时的偿债金额，后续地产竞拍款另列，避免把拍卖所得混作本次实付款。

直接读取已有focus.result及ASSET_LIQUIDATED事件，无新结算命令、账本或存档字段，AI适用相同展示。明细刷新后仍可从原存档恢复，不重复扣款；新回合或普通现金付租不显示。旧存档若保留了偿债事件可直接展示，若缺少应付或实付记录则不猜测历史金额。

独立明细区位于操作说明之后，保留原竞拍、回合和结算按钮；不使用弹窗或强制暂停。核心利息、自动偿债顺序、破产及默认轮数完全未修改。
