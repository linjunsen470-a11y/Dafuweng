# 主游戏山路补给街与镜头复核

仍为主游戏 `/` 山海都市岛，保持120格、123连接、经济、四级升级上限与旧存档，不添加新路网或平行经营系统。

## 镜头复核

读取上一轮实际99号政策存档，未修改玩家或地图状态。通过真实旋转按钮、鼠标滚轮、右键拖动和反向旋转复查，记录每步相机位置、目标、观察中心及距离。等待按实际绘制帧数计算，不把固定秒数到期当作动画已经结束。实测旋转后目标清空、残差0；镜头距离从35.90缩至27.78，等待160帧仍保持27.78。右键平移改变观察中心、反向旋转也正常清除目标。未复现持久残差或缩放回弹，故保留镜头实现，不声称覆盖全部设备或中途打断动画的情况。测量见 `qa/hill-camera-baseline-report.json`，玩家、地产、公司、回合、随机状态和阶段均与加载存档一致。

## 山路区域

选择原有102号卡片屋及101/103住宅所在山路。102有真实到店点券补给和卡片/道具兑换功能，原通用商店缺少区域身份，附近孤立高楼与大片平地也割裂了老街和山路。

新增原创216三角形山路补给铺：低矮双坡绿屋顶、木色门廊、卡片陈列柜和货箱，替换102的通用外观，功能沿用原到店货架。101、103两块住宅复用项目已有四级绿灰骑楼，产权和等级仍取真实状态，没有新增住宅规则。106号原地块距另一段主路过近，保持原状。

用三层低矮梯田、四株小果树和步道替换原31,-4处背景高楼，将补给铺、原材料公司和山路转弯连接起来。梯田最高0.76，树冠保持低矮；植物和建筑来自项目代码，不使用外部素材。景观步道不是可行走棋盘路线，没有加点券、额外事件或收益。

模型源：`art-source/shanhai/hill-supply.blend`；生成器：`scripts/art/create_hill_supply.py`；运行模型：`public/shanhai/models/hill-supply.glb`。梯田与果树：`src/engine/HillStreet.js`。

## 页面范围与余项

页面脚本明确准备101号人类起点，保留原资金、卡片、道具和随机状态，使用原有遥控卡1步到102，实际查看到店货架并兑换一张卡；使用原有遥控道具6步经103—107回48主路。重试完整走通至第3轮48号，现金20,000、点券147；手机另用准备的101二级/103四级住宅局面查看模型，实际101→102打开到店货架、关闭返回，不声称自然升级或手机已经兑换。

13项局部检查通过：设施对所有道路净空、两块住宅和梯田/树冠边界、模型尺寸、原拓扑未变，以及原有产权材质和老街取景逻辑。桌面旋转图是按下按钮后的过程视角，镜头完成性单独由前述实测记录验证。

首次到店兑换成功：赠60点券后180→147，实付33点券兑换遥控骰子，现金20,000不变。之后脚本选择到隐藏商店中的同名按钮，未能继续背包道具，属于测试选择器错误；保留失败报告，改为限定背包容器后从相同准备局面重试。果树根部按各自所在梯田层高对齐，修正后补查2项相关几何检查。

手机为Chromium软件WebGL视口，非实体手机/Safari；没有验收帧率、听感、长期平衡或自然完整对局。窄屏101号取景中，102侧边标牌仍部分出屏；到访102的商店可操作，但全区域窄屏构图仍待完善。其他旧高楼、106号拥挤地块、支路全住宅外观仍未完成统一。只做直接相关检查，不跑全量测试。
