# 主游戏山海都市岛：同格排布与局部遮挡

基于 `77837f9` 继续主游戏 `/`，不修改独立章节。改动限于显示，120格拓扑、123连接、经济、AI、角色ID、四级上限与旧存档结构均保持原样。

## 画面依据

前轮四人沿固定圆周站位，常规斜俯视下前排角色的帽子和身体遮住后排。真实页面确认，默认街景中101、102号格附近还会被 `(31,0,-4)` 的装饰高楼挡住人物和道路。原有淡化只处理原创海港住宅，不能处理该高楼。

基线见 `qa/harbor-visibility-baseline.json` 与 `before-crowd`、`before-mobile`、`before-tower` 截图。高楼基线截图同时包含回合提示，故后续除截图外也用实际模型视线检查核对遮挡；树木没有被该默认视角基线扫描认定为主要遮挡，本轮另用用户可旋转到的低角度视角验证。

## 实际改动

- 同一格的2–4名角色按编号沿镜头横向展开。四人时模型适度缩小，保持颜色、头顶编号和脚下标记；随镜头旋转调整排布与朝向，不把后排藏在前排身体之后。单独站立时恢复原尺寸和偏移。
- 排布只改变场景位置，不改变任何玩家的 `currentTile`。移动中的角色独立完成原跳跃动画，其他角色重新排布；到站后平滑入列。减少动画设置下，排布立即更新，不添加新镜头动画。
- 修复读档重建角色时重复注册同一呼吸/排布更新回调的问题，避免越读档更新越频繁。
- 现有局部淡化扩展到城市装饰高楼、树木及旧地产建筑。以屏幕内角色上身和当前地块为视线目标，挡住时降至22%不透明度，离开遮挡位置后恢复；产权底座与产权灯保留实色。
- 树木改为每棵独立材质，淡化一棵不影响相邻树。保留所有建筑和树木，不删景观、不改变布局、不新增依赖。仍沿用每180ms一次的包围盒判断。

所有新增显示逻辑与角色排布为项目原创代码，复用现有几何模型，没有引入外部素材。

## 针对性验证

- `npx vitest run harbor-pawn-visibility.test.js harbor-board-style.test.js`：6项通过；覆盖2–4人和多个镜头方向、居中与排序、遮挡淡化/恢复、邻树材质隔离、产权底座保留，以及原有格面/路网方向检查。
- `node test-main-harbor-visibility.js`：桌面1440×900四人同格、镜头转45度、101号高楼遮挡、9号低角度树木遮挡及恢复；比较镜头操作前后玩家、产权、轮次、随机状态不变。
- 实际点击掷骰进入12号银行：一人加入已有三人，稳定后四个编号保持横向分离；390×844触摸视口从四人同格出发，一人到12号，另三人留11号，存档中的位置仍是 `[12,11,11,11]`，HUD和银行按钮可用。
- 入列是平滑动画，首轮检查误在动画刚开始时断言最终排布；随后仅以 `--moves` 续跑移动和手机部分，等待模型尺度收敛再核对。此前已通过的镜头和遮挡检查保留在最终报告，未重复运行整套游戏测试。
- `npm run build` 构建最终两个入口；保留既有大分块警告，未跑全量测试、长期模拟或新增性能框架。

最终报告 `qa/harbor-visibility-browser-report.json`，单元检查 `qa/harbor-visibility-unit.log`，构建及哈希 `qa/harbor-visibility-build.log`、`qa/harbor-visibility-build-hashes.json`。最终街景截图为 `harbor-visibility-crowd-desktop.png`、`harbor-visibility-rotated.png`、`harbor-visibility-tower.png`、`harbor-visibility-tree-low-view.png`、`harbor-visibility-crowd-mobile.png`。

## 余项

角色仍是简化几何造型。拥挤时缩小模型有助于分辨人数，但不会提升面部细节；极远景仍较小。排布转换中可能短暂交叠，尚未做任意人数、任意镜头的全地图遮挡证明。包围盒判断偏保守，可能比实际挡住的部分淡化得更多；特殊设施、山体和部分特殊地标未全部纳入。

测试使用准备好的四人位置与少量真实掷骰，未完成自然整局；手机是浏览器触摸视口模拟，不代表实体手机、iOS Safari或稳定帧率验收。本轮未做主观音频验收。原有手机修复保留，第五级未开放。不推送、不发布、不绕过Space认证。
