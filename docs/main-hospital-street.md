# 主游戏阳光医院街区与手机升级窗口

2026-11-06，基于`46f6cd88a241d09db9f0d323f524a6b18c9512ba`，独立分支`cloud/dafuweng-playability`。只改主游戏`/`，山海都市岛；独立章节`/shanhai.html`未接入本轮修改。

## 依据与实际流程

从已有四人开局存档明确准备人类位于71号，资金、卡片、AI和RNG保持原值。通过页面使用原遥控骰卡走71→72；第1轮实际触发医院，医院停留数为1、现金20,000不变。AI正常执行，原有新闻通过页面关闭；第2轮人类回合按规则跳过，第3轮回到72号恢复行动，住院数为0、现金仍20,000。再用原遥控骰道具走72→73，打开购地窗口并选择放弃。不是自然完整对局，也不是改引擎强制跳过回合。

执行轨迹确认人类仅在第1轮到72、第3轮离开到73，第2轮没有移动命令。72医院的原规则是暂停下一次行动后从原格继续，不会自动传送其他位置，也不扣医疗费。本轮没有改这些规则。入院与恢复的完整状态、命令和截图见`qa/hospital-street-final-report.json`及同前缀PNG。

原到达提示只说“需要暂时休养”，入院反馈只说“暂时无法行动”。现在到达提示说明通常暂停1次、从当前格继续、角色/卡片可改变结果；入院回执使用实际受罚者和实际剩余次数，避免嫁祸或已有住院时长情况下显示错误对象/次数。没有额外弹窗。

## 地图与原创外观

72号复用上轮安全院址(−59,−16)，以原创程序化低层疗养院替换通用发光小屋。15个网格、216三角形；暖石墙、青绿檐顶、朝道路的入口雨棚、小日光徽记，标牌直接写明编号、医院名称与休养规则。局部高度低于2.7，几何保持在原1.92半径内，不盖住主路或118支路；固定落地高度0.22，取消旧通用设施的悬浮偏移。

前庭铺面、两处低花槽与座椅接既有医院步道，位于71/73地产之间；没有新增地块或设施功能。120格、123连接以及完整地图数据（含上轮院落位置）、经济和存档结构均不变。`qa/hospital-street-map-comparison.json`给出完整对比和几何统计。

## 手机升级窗口

前轮已实际操作118号手机升级，确认按钮可用，但建筑图集帧被宽卡片与固定高度压扁。本轮将窄屏图集帧固定为124×124且禁止flex压缩；首轮页面复查发现仅固定图片会挤掉标题与说明，因此进一步使用左图右说明的紧凑网格，街区名独占一行，保留正文滚动与底部固定操作按钮。浏览器实测124×124、预览无内容溢出、正文可滚动、升级按钮底边618px处于640px视口内。明确准备117号及118一级产权，经原遥控卡走到118，滚动查看现金预览后点击升级：20,000→17,832，一级→二级，目标产权不变、切换`res_civic_2`。结果记录于`qa/hospital-street-upgrade-report.json`，不是自然购地升级。

## 验证与限制

- 3个相关测试文件10项通过：医院模型净空、医院/AI原规则与提示对象、地图数据、三块前轮院落及街景。没有跑全量测试。
- 桌面1280×800及360×640视口实际操作、截图。完整医院流程以桌面开始，再仅缩窄视口继续操作；不等于实体手机。手机升级另以触控设备视口新开页面。
- 预检脚本先误用不存在的镜头方法；第二次因切换浏览器设备类型触发页面重载，未完成离院。已保留两次失败报告和截图，改为仅调整视口后完整流程通过。单测初次将保存时间戳也作相等比较，排除`savedAt`后通过。上述均未通过修改游戏规则规避。
- 手机图修复的中间版本分别暴露内容裁切与网格行压缩，保留失败截图；最终以内容高度确定行高，断言与实际升级通过。
