# 手机购地阅读与按钮区域（2026-11-06）

## 实际观察

在Chromium手机视口中从空存储开启两图四人局：蓝湾海岸360×844、枫谷山城390×844，启用触摸模拟、减少动画和AI速览。通过界面选择四人、开始、收起指引、遥控2步、购地、结束回合，让三名AI行动至第2轮，然后保存、打开暂别窗口并取消、刷新继续。

修改前的两图均出现相同问题：

- “实付购地 / 支付后现金”标签为11px浅色文字，金额15px，挤在同一行，资金取舍不突出。
- 保存和返回按钮只有30px高，保存按钮宽44px；路过、节奏和AI速览按钮40px高。手机辅助操作比主按钮更难准确点击。

修改前截图及计算样式见qa/mobile-decisions-baseline-report.json。没有把浏览器触摸模拟当作真人或实体手机测试。

## 修复

只修改680px及以下的CSS，不改页面结构、事件绑定或规则。

购地/升级报价使用两列分组，各自把标签和金额分行，标签14px，金额20px，深色数字并保留货币符号。加深操作说明、风险与细则文字，保留租金、前方风险和委托奖励说明，避免为了缩短页面删掉决策信息。

游戏区及窗口中的次要按钮、节奏按钮、保存和返回按钮最小高度44px；保存和返回各占半行，有明确背景和边界，文字13px。主行动仍保留原突出样式，不增加浮动工具栏、弹窗或额外入口。

## 验证

- 修改前与修改后分别运行 `node test-shanhai-mobile-decisions.js --baseline` / 不带参数：两图真实页面触摸操作、四人首轮、保存、取消暂别与刷新恢复。
- 记录购地关键字号和按钮实际区域；修改后标签≥14px、金额≥20px，路过、节奏、AI速览、保存与返回高度均≥44px。360/390px没有横向溢出。
- 同一页面切换到1100px宽度复查桌面断点，关键元素计算样式与修改前完全一致。这里是桌面宽度布局检查，没有声称做了全部桌面鼠标场景。
- 两图前后最终玩家、产权、RNG、轮数及slice存档逐项一致；刷新不改变余额或重复购地。
- `npm run build:shanhai` 通过，保留既有包体大小提示。哈希见qa/mobile-decisions-build-hashes.json。

已查看两图修改后的手机截图，金额分组、风险说明及买地/路过按钮均完整可见。

本轮只有样式修改，没有新增规则单元测试或运行全量测试。截图仅内部验收，不入恢复包。

## 限制与后续
